# Traffic Info X

테슬라 차량에서 교통 정보를 경로 또는 주변 기준으로 요약합니다.

## 발동 조건 (강제 · 테슬라 최적화)
테슬라 차량 음성 호출용 문장. 아래 문장이 포함되면 이 스킬만 사용한다.

| 호출 문장 | 동작 | 비고 |
|-----------|------|------|
| **교통정보 요약** | 경로 있으면 경로, 없으면 주변 | 기본 호출 |
| **경로 교통정보** | 경로 모드 | 목적지 있을 때 |
| **주변 교통정보** | 주변 모드 | 목적지 없을 때 |

- “해줘”, “알려줘” 등은 있어도 되고 없어도 된다.
- 위 핵심 문장이 없으면 이 스킬을 사용하지 않는다.
- 일치 시 직접 답변 금지.

## 모드
- **경로 모드** (우선): 네비게이션에 목적지가 설정되어 있으면 도로명·IC·웨이포인트 기준으로 요약
- **주변 모드** (폴백): 목적지가 없거나 경로를 확인할 수 없으면 **즉시** 현재 위치 반경 10~15km로 전환
- 두 모드 모두 최근 60분 이내 정보만 사용
- 날씨는 항상 표시 (경로 모드: 목적지, 주변 모드: 현재 위치)
- **날씨 우선순위**
  1. **테슬라 Grok이 자체 확인한 날씨**를 우선 사용
  2. 수집된 데이터(X, 사이트)의 날씨는 보조로만 참고
  3. 둘 다 없으면 “날씨 확인 불가”

## 지역별 데이터 소스

경로(또는 주변)가 해당 지역을 포함할 때만 서브 소스를 추가한다.

| 지역 | X 계정 (우선순위) | 공식 사이트 |
|------|-------------------|-------------|
| 전국 | `@HappyTraffic` | its.go.kr |
| 서울 | `@seoultopis` > `@smartroad` | topis.seoul.go.kr |
| 부산 | `@Busan_TIC` | its.go.kr |
| 대구 | `@poltra053` | its.go.kr |
| 경기 | `@16889090` | its.go.kr |
| 인천 | `@poltra032` | its.go.kr |
| 광주 | `@TBNGwangju` | its.go.kr |
| 대전 | `@poltra042` | its.go.kr |

- 메인을 먼저 확인하고, 지역 서브는 보조로 교차 확인
- 서브에서 더 구체적인 정보가 있으면 우선 반영
- 비활성·정보 없는 계정은 무시

## 출력 형식
```
### [출발지] → [목적지] 또는 주변 교통

**날씨**: [상태, 기온]   ← 최상단 (테슬라 Grok 확인)
**주요 구간**
- [도로/IC]: 🟢/🟡/🔴 (네비게이션 기준)
  - 추가: [X/사이트에서 확인한 사고·공사 등]
**예상 소요**: XX~YY분 (신뢰도: 중간)
**주의**: ...
**확인**: [its.go.kr](https://its.go.kr)
```
음성용은 위 내용을 2~3문장으로 축약한다.

**음성 예시**  
“목적지 맑고 14도입니다. 경인고속도로 서행 중이고, 김포IC 부근 공사가 있습니다. 예상 25분에서 35분입니다.”

## 에이전트 팀 (병렬 수집)

교통 정보 수집을 역할별 서브에이전트로 나누어 병렬 수행한다.

| 서브에이전트 | 역할 | 소스 |
|--------------|------|------|
| WeatherAgent | 날씨 수집 | 날씨 도구 |
| TrafficXAgent | 사고·공사·정체 원인 | X 계정 (메인 + 서브) |
| SiteAgent | 공식 데이터 교차 확인 | its.go.kr / TOPIS / UTIC |
| FusionAgent | 결과 융합·필터링·요약 | 위 3개 결과 |

### 통신 프로토콜
각 에이전트는 아래 형식으로 결과를 반환한다.

```
{
  "agent": "WeatherAgent | TrafficXAgent | SiteAgent",
  "status": "success | failed | timeout",
  "data": { ... },
  "error": "메시지"
}
```

- FusionAgent는 `status: success`인 결과만 사용
- `failed`/`timeout`은 “확인 불가”로 표기
- 추가 메시지 교환 없음 (단방향 결과 전달)

### 실행 규칙
- 타임아웃: 에이전트당 15초
- 재시도: 실패 시 1회 (해당 에이전트만)
- WeatherAgent, TrafficXAgent, SiteAgent는 **가능한 경우 동시** 시작
- 동시 실행이 불가능하면 순차 실행하되, 한 에이전트 실패가 다음을 막지 않음
- FusionAgent는 성공한 결과만 사용

## 데이터 융합
1. **테슬라 네비게이션 교통량**을 최우선으로 사용 (원활/서행/정체, 예상 소요)
2. 그 위에 X·사이트에서 확인한 **원인(사고·공사·통제)**을 추가로 설명
3. 네비게이션 정보가 없으면 X → 사이트 순으로 대체
4. 최근 60분 이내만 사용
5. 날씨는 별도 우선순위 적용

상세 공식은 `references/details.md` 참조.

## 출력
위 출력 형식을 따른다.  
상세 기준(신뢰도, 심각도, 차선, 우회, 예측)은 `references/details.md`를 참조한다.

## 장애 조치
- **격리**: 한 에이전트 장애가 다른 에이전트로 전파되지 않음
- **부분 가동**: 일부 에이전트만 성공해도 요약 생성
- **타임아웃**: 에이전트별 개별 적용
- **재시도**: 실패 시 1회 (해당 에이전트만)
- **강등**: 전부 실패 시 “정보 없음”으로 안전 종료
- **관측**: 모든 장애는 출력에 명시 + 신뢰도 감점
